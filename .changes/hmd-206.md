### Changed

- **Heimdall runs on Loom 0.18** (HMD-206). The Hub, Collector, and dashboard find their configuration file with Loom's lookup. It reads the first `.config/heimdall/<binary>.toml` or `.json` in the working directory and each directory above it below home, then the same file in home, then `config.toml` or `config.json` in `$XDG_CONFIG_HOME/heimdall-<binary>`, such as `~/.config/heimdall-hub` by default. Before, only the working directory and home were tried.
- **A file that does not parse is skipped with a warning** (HMD-206). The binary then runs with no configuration file. A bad value inside a file still stops `serve` and `run` when it is in a section Heimdall checks itself: `[delivery]`, `[conditions]`, `[sessions]`, and `[updates]`. A top-level setting with the wrong type, such as a text `sleeps`, or one its option rejects, such as an `insight_reader` that is not a role name, is dropped and named at `-v`, and the option falls back to its default.
- **Help pages show each option's variable and configuration key** (HMD-206), as `env:` and `config:` lines.
- **A TOML date or time value inside a section Heimdall checks now reaches its checks as text** (HMD-206), so `topic = 2026-01-01` is accepted as the topic "2026-01-01". Loom reads dates that way.
- **`service install --port` refuses to create `hub.toml` or `dashboard.toml` when the binary's XDG configuration file exists** (HMD-206), as it already did beside a `.json` file of the same name, because the new file would hide it.

### Added

- **`--no-config`** (HMD-206). Every binary runs without reading a configuration file when given it, so a dotfile cannot change a run.
